# 실험 기록 운영 규칙

저장소: https://github.com/Simon-Beck12/npl-el (private). 기준 사본은 `/home/beck/바탕화면/npl-el-pipeline`다.
사용자, 브라우저 Claude, VS Code Claude Code가 같은 규칙을 따른다.

| 파일 | 역할 |
|---|---|
| `docs/EXPERIMENTS.md` | 실험 대장(맨 위 표) + 실험 명세(아래 항목). 기각·중단도 지우지 않는다. |
| `docs/DATASETS.md` | 데이터셋 명세. 원본, 파생 데이터, 파생 뷰, 테스트셋. |

## 1. ID 규칙
- 실험: `EXP-001`부터 순서대로. 번호는 재사용하지 않는다.
- 원본 데이터셋 `DS-01`, 파생 데이터(파일 생성) `SYN-001`, 파생 뷰(파일 없이 코드로 변환) `DV-01`.
- 파생 데이터를 다시 만들면 새 버전을 쓴다: `SYN-001-v2`. 이전 버전은 지우지 않는다.

## 2. 상태와 판정
- 상태: `계획` → `실행중` → `완료` / `중단(오류)` / `보류`.
- 판정: `채택` / `기각` / `보류` / `-`(아직 없음).
- 판정은 실행 전에 적은 기각 기준으로만 내린다.
- 결과를 본 뒤 기각 기준을 바꾸지 않는다. 바꿔야 하면 "변경 이력"에 날짜와 이유를 남긴다.
- 비교 기준선은 같은 파이프라인·같은 seed로 다시 계산한 값을 쓴다. seed별 짝 비교를 우선한다.

## 3. 기록 시점 (한 실험에 3번)
1. 실행 전: 대장 표에 행 추가(상태 `계획`). 배경, 목적, 가설·기각 기준, 절차를 쓴다. 커밋·push.
2. 실행 시작: 시작 시각(KST), 커밋 해시, 실행 명령, 출력 폴더를 쓴다. 상태 `실행중`. 커밋·push.
3. 실행 종료: 종료 시각, 결과 표 1개, 결과 파일 경로, 판정과 이유, 다음 할 일을 쓴다. 대장 표의 상태·판정·핵심 결과도 고친다. 커밋·push.

## 4. 작성 규칙
- 한국어 STE. 한 줄에 정보 하나. 숫자와 단위를 쓴다.
- 결과 숫자는 결과 파일 경로와 함께 쓴다. git에서 제외된 파일은 경로 뒤에 `(로컬)`을 붙인다.
- 결과 표 아래에 "지표 종류, 임계값, 집계 방식"을 한 줄로 쓴다.
- 같은 조건인데 이전 기록과 숫자가 다르면 "주의" 줄에 적는다.
- 사후에 복원한 기록은 시각 옆에 `(사후)`를 붙인다.
- 기존 항목은 지우지 않는다. 틀린 내용은 취소선(`~~ ~~`)으로 남기고, 옆에 날짜와 취소 이유를 쓴다.
- 테스트 데이터나 기대값을 바꾸면 "변경 이력"에 따로 적는다.

## 5. 커밋 규칙
- 메시지 접두어: `init:` 초기, `log:` 실험 기록, `data:` 데이터셋 명세, `feat:` 코드, `fix:` 수정.
- 메시지에 관련 ID를 쓴다. 예: `log: EXP-003 결과 기록`.
- 작업 시작 전 `git pull`. push 전 `git ls-files`로 데이터 파일과 1 MB 넘는 파일이 없는지 확인한다.
- 데이터, 가중치, 대용량 결과는 커밋하지 않는다. 각 데이터의 라이선스와 이용 약관을 따른다.
- 강제 push를 하지 않는다.

## 6. 역할
- Claude Code: 실험을 실행하면 3절의 1~3을 직접 기록하고 커밋·push한다. 보고의 숫자와 기록의 숫자가 같아야 한다.
- 브라우저 Claude: 저장소를 연결해서 읽고 검토한다(숫자 불일치, 기각 판단, 규칙 위반). 사용자가 요청할 때만 커밋하며, 커밋 전 `git pull`을 한다.
- 사용자: 판정이 애매하면 결정한다. 결정 내용은 Claude Code가 "(사용자 결정, 날짜)"로 기록한다.
